# Step 1 — Backtest Integrity and Trusted Baseline Reconstruction

## 1. Purpose

The revised paper is about the performance of an **integrated portfolio-construction architecture**.

Before testing which portfolio component adds value, the existing backtest must first be made completely trustworthy.

Step 1 answers:

> **Are the existing portfolio P&L, weights and reported metrics generated by a causally correct, reproducible and internally consistent walk-forward process?**

Do not optimize performance in this step.

The output of Step 1 becomes the single trusted foundation for all later:
- asset-selection experiments;
- BL vs MVO comparisons;
- ML-view ablations;
- confidence experiments;
- regime experiments;
- transaction-cost analysis.

# 15. Audit portfolio return mechanics

Verify exactly how daily NAV is computed.

If target weights are formed at `t`, the strategy must not earn `r_t` if that return was already observed before the weights were formed.

Determine whether between scheduled rebalances the implementation:

- keeps share holdings fixed;
- keeps portfolio weights fixed;
- re-normalizes daily;
- implicitly rebalances every day.

Document the actual rule.

For a standard buy-and-hold-between-rebalances implementation, weights should drift with asset returns until the next scheduled trade.

# 16. Add turnover bookkeeping now

Transaction costs will be analyzed later, but turnover must be measurable from the trusted baseline.

At each rebalance calculate pre-trade weights and target weights.

One standard definition:

\[
Turnover_t =
\frac{1}{2}
\sum_i
|w^{target}_{i,t} - w^{pre}_{i,t}|.
\]

Store:

```text
date
asset
pre_trade_weight
target_weight
weight_change
```

and portfolio-level turnover.

Output:

```text
outputs/step1/trusted_baseline_turnover.csv
```

# 23. Step 1 completion criteria

Step 1 is complete only if:

### Causal correctness
- no future feature information;
- no unavailable target labels;
- no same-period return leakage;
- execution timing is explicit.

### Reproducibility
- code reproduces trusted results deterministically;
- seeds and environment are recorded.

### Portfolio correctness
- weights sum correctly;
- constraints are enforced;
- NAV compounding is verified;
- turnover is recorded.

### Architecture correctness
- asset selection is reproducible;
- BL inputs / posterior are reproducible;
- ML predictions are reproducible.

### Numerical consistency
- MVO inconsistency is explained and resolved.

### Documentation
- current universe construction is known;
- all main parameters have provenance.
